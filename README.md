# Pokerist HUD Education — визуальный тренер Техасского Холдема

Локальное Python-приложение: захват экрана → консервативное распознавание →
стабилизация → Monte Carlo → полупрозрачный обучающий HUD на русском.
**Не управляет игрой**, не нажимает кнопки и не читает память процесса.
Используйте только там, где правила игры разрешают внешние подсказки; для
обучения без клиента есть встроенный тренажёр.

## Профиль по присланным скриншотам Pokerist 3D

Для вида стола **1280×719** добавлен стартовый профиль:
[описание, результаты и ограничения](profiles/pokerist_3d_1280x719/README.md).
В панели запуска нажмите **«★ Профиль по вашим скриншотам»** — потребуется
выделить только один прямоугольник изображения игры, остальные зоны уже
расставлены. Сохранение добавит образцы **13 карт**, пустых слотов и доступных
цифр без удаления ручных шаблонов. CLI: `python main.py --profile --delay 4`.

Это неполная колода и не готовый OCR всех чисел: банк на префлопе отсутствует,
часть сумм и затемнённых кнопок пока остаются неизвестными. В профиле число
оппонентов задаётся вручную. Примеры протестированы на исходных кадрах, не на
независимых новых раздачах. Профиль содержит небольшие вырезки; полные исходники, добавленные пользователем,
находятся в `photo example/`.

## Простой запуск и настройка поверх игры

**Windows:** двойной клик по **`start_windows.cmd`**. Первый запуск создаст
виртуальное окружение и установит зависимости, затем откроет панель:
**разметить стол → собрать шаблоны → проверить кадр → запустить HUD**.
Требуется установленный Python 3.10+ с Tcl/Tk. Linux/macOS: `sh start_desktop.sh`.

Подробная инструкция для ПК: **[QUICKSTART_RU.md](QUICKSTART_RU.md)**.
В редакторе и сборщике теперь есть «Новый кадр (3 с)»: можно переключиться
на игру, окна помощника скроются перед захватом. Существующая разметка
загружается для редактирования; перед перезаписью создаётся `config.json.bak`.
В Windows заголовок окна можно задать **до** разметки для автоматического
выбора клиентской области. Это отдельный редактор, не внедрение в игру.

## Запуск

Python **3.10+**, графическая сессия рабочего стола, Tk.

```bash
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# Linux/macOS:
source .venv/bin/activate
pip install -r requirements.txt
python main.py --demo
```

На Windows в установщике Python включите Tcl/Tk. На Ubuntu/Debian нужны
системные `python3-tk` и `python3-venv`; на macOS — Python с поддержкой Tk
(например, официальный установщик). OpenCV используется **headless**: его GUI
и libGL не нужны, интерфейс целиком на Tk. Захват требует разрешения системы
на запись экрана. Для Linux предпочтительна X11; на Wayland `mss` может не
иметь доступа к содержимому окна. Свернутые и перекрытые окна не распознаются.

```bash
python main.py --calibrate             # разметка и первые шаблоны
python main.py --collect --delay 4     # время переключиться на игру
python main.py --check --delay 4       # снимок с рамками и отчёт captures/
python main.py --run                   # захват + HUD
python main.py --demo --seed 42        # тренажёр без игры и config.json
python main.py --run --iterations 5000 # >= 2000, по умолчанию 3000
python main.py --help
python -m pytest -q
```

`--config PATH` и `--templates PATH` позволяют держать отдельные профили для
браузера и эмулятора. Пути по умолчанию относительны рабочей папке.

## Первичная настройка примерно за 3 минуты

Три минуты — ориентир для первой разметки и нескольких примеров, **не обещание
собрать всю колоду**. Без образцов ещё не виденных карт HUD честно покажет
«не распознано» вместо рекомендации.

1. **0:00–0:30.** Откройте стол в обычном масштабе, уберите перекрывающие окна.
   Запустите `--calibrate`. На замороженном скриншоте выделите **клиентскую
   область** игры: без рамки ОС. Для браузера это вся клиентская область
   браузера, включая его панели, если используете привязку к окну Windows.
2. **0:30–1:30.** Мышью выделите `hero1`, `hero2`, `board1`…`board5` —
   **каждую карту целиком**, одинаково плотно. Пустые позиции борда также
   разметьте. Затем `pot`, `stack`, `call`: только строку числа, без подписи
   «Pot», знака валюты и графики кнопки. **Ноль должен отображаться как 0**;
   слово Check не подменяется числовым нулём.
3. **1:30–2:00.** Разметьте `opp1`…`opp8` только у реально существующих мест:
   участок рубашки, который исчезает при фолде. Не включайте имя/аватар.
   Опционально `oppstack1`…`oppstack8`: стеки соответствующих мест.
   Нажмите «Сохранить config». В Windows задайте уникальную часть заголовка
   окна игры: будет отслеживаться **нативная клиентская область**, движение
   и изменение размера. Выделение должно совпадать с этой областью.
   На Linux/macOS оставьте заголовок пустым: область фиксированная,
   после перемещения окна нужна повторная калибровка.
4. **2:00–3:00.** «Собрать шаблоны»: выберите ROI в выпадающем списке —
   вырезка уже выделена. Тип `card`, метка `Ah`, `Kd`, `Tc` и Enter.
   Либо выделите нужную часть мышью. `T` — десятка, масти `c d h s`.
   Для **каждого вида пустого слота** выберите `empty` и метку `empty`;
   для рубашки — `back`, метка `back`. Пустые места оппонентов тоже требуют
   образцов `empty`. Образцы разных фонов можно сохранять под одной меткой.
5. Для цифр выберите `glyph`, выделяйте **один символ**, подпишите `0`…`9`,
   `.`, `,`, `K`, `M`, `B`, Enter. Вертикальный размер каждого вырезанного
   символа, включая точку, должен совпадать с высотой всей числовой строки;
   ширина — с ячейкой символа, без соседних цифр. Сохраните варианты шрифтов
   банка, стека и кнопки. После этого запустите `--run`.

Пополняйте `templates/` по мере появления новых карт. Кнопка «Скриншот в базу
шаблонов» в HUD открывает последний захваченный кадр; закройте сборщик для
перезагрузки шаблонов без перезапуска. Для следующего снимка откройте его снова.
Также доступна кнопка «Новый кадр (3 с)» непосредственно в сборщике.
Можно сохранить несколько образцов каждой карты при разном размере/освещении.
Не смешивайте в одном профиле несовместимые темы и разные колоды.

### Масштаб и относительные координаты

В `config.json` ROI хранятся как доли `x, y, width, height` от клиентской
области (0…1, то есть проценты / 100), а не как координаты пикселей.
Масштабирование работает при **пропорционально сохраняющейся вёрстке**.
Переход 16:9 → 4:3, появление боковой панели, изменение зума браузера без
изменения клиентской области или новая вёрстка требуют перекалибровки.
Автоматического поиска стола по произвольному рабочему столу нет.

## HUD

- Поверх окон, прозрачность 93%, перенос за верхнюю полосу, обычная рамка ОС.
  В Windows по возможности ставится справа от выбранной области.
- Карты цветные: ♥ красная, ♦ синяя, ♣ зелёная, ♠ чёрная. Это условные цвета
  HUD; распознаются и обычная, и четырёхцветная колоды по вашим образцам.
- `−` / `+`: ручной режим 1…8 оппонентов; «Авто» возвращает распознавание.
  Для авто нужно разметить **все места**, на которых могут быть соперники.
- «Обучение»: подробное объяснение или компактный текст рекомендации.
- «Тестовая раздача»: переключение на синтетическую ситуацию. Галочка
  «скрыть расчёт» оставляет карты, банк и колл для самостоятельного ответа.
  «Вернуться к столу» возобновляет показ реальных данных.
- При неизвестной карте, числе, невалидном борде, дубликате или анимации
  **устаревшие рекомендации скрываются**. Для восстановления нужны два
  одинаковых состояния с интервалом не менее 250 мс (захват каждые 275 мс).

## Распознавание и ограничения точности

`vision.py`: CLAHE → Оцу, нормализация высоты, `matchTemplate` в масштабах
0.9/1.0/1.1, HSV-профиль цветных/чёрных чернил как дополнительная проверка
формы полной карты. Несколько шаблонов на метку, порог 0.84 и отрыв от другой
метки 0.04. Для пустых участков — сравнение внешнего вида: корреляция
константных картинок математически ненадёжна. Цифры — независимые шаблоны,
NMS по X, отбрасывание неоднозначных меток и непокрытых областей текста.

**Confidence — similarity score, не калиброванная вероятность правильности.**
Два стабильных неверных кадра всё ещё могут быть ошибкой. Перед сессией
проверьте карты/банк/колл на нескольких известных ситуациях. Автоматически
гарантировать точность на неизвестном оформлении Pokerist невозможно.
Образцы реального клиента не включены: чужие шаблоны ухудшали бы надёжность.

Числа: `1.5K`/`1,5K` = 1500; `1,234`/`1.234` = 1234;
`1,234.50`/`1.234,50` = 1234.5; `M` = 10⁶, `B` = 10⁹.
Один разделитель с **тремя цифрами справа считается группировкой**:
`1.234K` = 1 234 000. Если ваша локаль выводит именно три десятичных знака,
такой формат неоднозначен — смените формат/локаль или адаптируйте парсер.
Неизвестные символы не считаются нулём. Из-за округления интерфейсом
«1.2K» всё равно является приблизительной исходной величиной.

Захват/CV и расчёт эквити идут в отдельных потоках, Tk обслуживается только
в главном потоке. Для расчётов очередь хранит только свежую задачу;
результаты старого состояния не показываются. Это **не click-through HUD**:
окно интерактивное и не должно перекрывать захватываемые ROI.

## Что именно считает тренер

- Чен: старшая карта, пары, одномастность, гэпы, коннекторы; категория руки и
  предупреждение о мультивее. Это **не позиционный чарт открытия**.
- Готовая комбинация: Treys, с уточнениями для топ-пары/топ-кикера, оверпары,
  сета и трипса. На общем сильном борде комбинация может принадлежать всем.
- На флопе/терне перечисляются карты завершения флеш-дро, OESD, гатшота,
  двойного гатшота и условные ауты на пару оверкарт. Объединение множеств
  исключает дубли (например, червовая десятка одновременно закрывает два дро).
  Не учитываются все возможные улучшения ранга руки, бэкдоры, редро,
  натсовость и карты, которые одновременно усиливают соперника.
  Уже готовые более сильные комбинации не «улучшаются» слабым дро.
- Правило 2/4 сравнивается с **точной комбинаторной вероятностью увидеть
  хотя бы один из текущего множества аутов** к риверу:
  `1 − C(неизвестных − ауты, оставшихся улиц) / C(неизвестных, оставшихся улиц)`.
  На флопе правило ×4 предполагает, что вы увидите **обе** следующие карты.
- Независимо Monte Carlo (по умолчанию 3000) оценивает **долю банка на
  вскрытии**, включая ничьи, против 1…8 равномерных случайных рук, карты
  сдаются без возвращения. Примерная 95%-погрешность — по дисперсии доли банка.
  «Точный Monte Carlo» — противоречие: это оценка, не полный перебор.
  Вероятность попасть в ауты и эквити не равны, особенно при оверкартах.
- `Pot Odds = Required Equity = Call / (Pot + Call)`.
  **Pot — весь текущий банк, уже включающий ставку соперника, но не ваш колл**.
  `EV(call) = Equity × (Pot + Call) − Call`; также выводится EV / Pot.
  Без рейка, будущих вложений, fold equity и side pots.
  Если Call > стек героя, расчёт отклоняется: нужны доступный all-in и
  корректный разыгрываемый банк. Другие side-pot ситуации следует разбирать
  отдельно, текущая модель их не распознаёт.
- `SPR = эффективный стек / текущий банк`. При распознанных стеках всех
  активных соперников берётся `min(стек героя, max(стеки соперников))`.
  Иначе выводится явно помеченная **верхняя оценка по стеку героя**.
  Это эвристика глубины, **не вычисленные implied odds**. Разные попарные
  эффективные стеки и вложения на текущей улице здесь не моделируются.
- Положительный EV колла не означает, что рейз лучше или что будущая линия
  прибыльна. Диапазоны, позиция, размер рейза, рейк, будущие ставки и стратегия
  продолжения требуют отдельной модели. Тренер не объявляет рейз «строго +EV».

## История

`hands_log.csv`, UTF-8 с BOM, даты UTC. Одна запись **последнего наблюдаемого
решения** на раздачу: карты, борд, банк, колл, эквити, EV, рекомендация,
оппоненты, источник (`screen` или `demo`), причина окончания.
Сохраняется при смене карт героя/сбросе борда, уверенном исчезновении обеих
карт героя на секунду, смене режима и штатном закрытии HUD.
Это не восстановленная серверная история и не результат вскрытия.
Две подряд одинаковые руки без видимого промежутка могут быть неразличимы;
аварийное завершение может потерять текущую несохранённую раздачу.
Конфигурация, резервная копия, шаблоны, снимки, журналы запуска и история исключены из Git.

## Структура

| Модуль | Ответственность |
|---|---|
| `main.py` | CLI, режимы запуска, отсчёт до захвата |
| `bootstrap.py`, `start_windows.cmd`, `start_desktop.sh` | Подготовка окружения и запуск панели |
| `desktop_launcher.py` | Панель настройки без командной строки |
| `capture_ui.py`, `setup_support.py` | Скрытие окон перед новым кадром, выделения, команды запуска |

| `calibrator.py` | Мышиная разметка, сбор и подпись шаблонов |
| `screen.py` | Относительные ROI, MSS, Windows client-area tracking, DPI |
| `vision.py` | Шаблоны, HSV, числа, NMS, валидация и debounce |
| `poker_coach.py` | Чен, комбинации, дро, equity MC, odds/EV/SPR, объяснения |
| `hud_overlay.py` | Tk, capture/CV worker, MC worker, тренажёр |
| `hand_history.py` | CSV и границы раздач |
| `tests/` | Математика, парсер, синтетический CV, debounce, CSV |

## Проверки и границы верификации

```bash
python -m pytest -q
python -m compileall -q main.py calibrator.py screen.py vision.py poker_coach.py hud_overlay.py hand_history.py
```

Автотесты проверяют математические инварианты и распознавание **синтетических**
изображений, не доказывают качество на реальных скриншотах Pokerist.
Для GUI нужен локальный рабочий стол: в headless-среде без Tk/дисплея нельзя
проверить оверлей, клики, разрешения MSS и native Windows tracking.
